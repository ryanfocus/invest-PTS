# 部署與換機器

這份文件回答一個問題：**這台電腦壞了，怎麼在另一台上把 PTS 重建起來？**

少做任何一步，PTS 會用不同的方式失敗，而且不一定馬上看得出來：平常沒有例行訊息，
最常見的症狀是「13:25 收到一則『盤中程式今天沒有跑』」。

---

## 換機器要重做什麼

| # | 步驟 | 少了它會怎樣 |
|---|------|------------|
| 1 | [Python 與虛擬環境](#1-python-與虛擬環境) | 排程記的是虛擬環境裡的 `pythonw.exe`，沒有就啟動不了 |
| 2 | [註冊群益元件](#2-註冊群益元件) | 連登入都做不到 |
| 3 | [**下單憑證**](#3-下單憑證) | **憑證綁電腦**，舊機器的不能複製。沒有它，報價、模擬都正常，真的要下單那一刻才被擋 |
| 4 | [不進版控的設定檔](#4-不進版控的設定檔) | `.env` 是帳密、期貨帳號與 webhook，版控裡沒有 |
| 5 | [排程](#5-排程) | 沒有人會叫醒 PTS |
| 6 | [電腦不能睡、要能自己登入](#6-電腦不能睡要能自己登入) | 睡著或停在登入畫面，排程就不會跑 |
| 7 | [**從舊機器複製資料**](#7-從舊機器複製資料) | **原始行情記錄重建不回來** |
| 8 | [驗收](#8-驗收) | |

第 3 步與第 7 步最容易被忽略，而後果最不對稱。

## 1. Python 與虛擬環境

Python 要 **64 位元**，和群益元件的位元數一致（用 `元件\x64` 那一組）。目前用的是 3.12。

```powershell
cd <專案資料夾>
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
```

全綠代表程式本身沒問題，**不代表連得上券商**：測試跑的全是假 broker，一個也不會登入群益。

> ⚠️ 排程記的是**絕對路徑**：虛擬環境的 `pythonw.exe` 與專案資料夾。重建虛擬環境、搬動專案
> 資料夾之後，要重跑一次 `tools\schedule.py install`（第 5 步）。

---

## 2. 註冊群益元件

群益 API 是 Windows 的 COM 元件，每台電腦都要註冊一次（需要系統管理員）。

1. 從群益 API 下載專區取得元件（目前用 2.13.58），把 `元件\x64` **整個資料夾**複製到一個
   **之後不會再動**的位置，例如 `C:\SKCOM`。註冊會把當下的絕對路徑寫進登錄檔，資料夾一搬
   就壞；只搬 `SKCOM.dll` 也不行，同資料夾的其他 DLL 都要在。
2. 以系統管理員身分開「命令提示字元」，在那個資料夾執行 `install.bat`
   （內容就是 `regsvr32 SKCOM.dll`）。看到「DllRegisterServer 成功」就好。
   失敗通常是缺 Visual C++ 可轉散發套件（x64）。

PTS 從登錄檔反查 `SKCOM.dll` 的位置，不寫死路徑。

> 📌 **換元件版本之後**：comtypes 會沿用舊版產生的介面檔。登入時出現「群益元件無法載入」，
> 刪掉 comtypes 產生的介面檔（`.venv\Lib\site-packages\comtypes\gen\` 底下的檔案）再試。

> 📌 新帳號第一次用 API 才需要：簽「期貨API服務下單聲明書」、跑官方的連線測試
> （`SKCOMVerifyDJ.exe`，沒跑過登入會回代碼 321）。這兩件事跟著帳號，不跟著電腦。

---

## 3. 下單憑證

**憑證綁這台電腦。** 舊機器上的不能複製過來，要在新機器重新申請（群益金融網「憑證專區 →
AP軟體憑證」的憑證精靈，會收一次簡訊驗證碼）。憑證裝在 Windows 使用者帳號底下——排程也因此
掛在同一個使用者底下（第 5 步）。

⚠️ **看報價不需要憑證，只有送出委託需要。** 憑證沒裝好時，模擬模式、報價、Discord 全都正常，
直到打開自動下單、第一筆委託送出去那一刻才被擋（PTS 會發「委託沒有送出去」並停止當天的進場）。
所以**打開自動下單之前**，先確認憑證精靈顯示「此電腦已安裝您的有效憑證」。

⚠️ 電腦裡不要同時有兩張憑證（例如舊的過期沒刪），登入會回代碼 600，訊息不會講原因是「有兩張」。

## 4. 不進版控的設定檔

**`.env`**：複製 `.env.example` 成 `.env`，照裡面的說明填。

```
CAPITAL_USER_ID          群益登入帳號（身分證字號）
CAPITAL_PASSWORD         群益登入密碼
CAPITAL_FUTURES_ACCOUNT  期貨帳號：期貨商代號 7 碼＋帳號 7 碼（只有自動下單需要）
DISCORD_WEBHOOK_URL      Discord webhook（只有 discord.enabled 為 true 時需要）
```

⚠️ `.env` 裡是可以直接下單的帳密。**不要經過雲端硬碟、聊天軟體、email 搬到新機器**——照著
舊機器的內容重新輸入，或用隨身碟複製後刪掉。

**`config/settings.yaml`**（進版控）：交易商品、每次進場口數、加碼上限、自動下單開關、Discord 開關。
每一項的意思寫在檔案裡。版控裡的自動下單**一定是關的**（有一條測試守著）；新機器先用模擬模式
跑，確認沒問題再打開。設定寫錯時，盤中程式一啟動就擋下來，原因寫在當天的 log。

## 5. 排程

用虛擬環境的 Python 執行（排程記下的就是它旁邊的 `pythonw.exe`），不需要系統管理員：

```powershell
.\.venv\Scripts\python.exe tools\schedule.py install   # 建立（或覆蓋）兩個排程
.\.venv\Scripts\python.exe tools\schedule.py show      # 查看現況：下次執行、上次結果
.\.venv\Scripts\python.exe tools\schedule.py remove    # 兩個都移除
```

| 排程 | 什麼時候 | 做什麼 |
|------|---------|--------|
| PTS 盤中程式 | 每天 08:40 起**每分鐘**叫醒一次，到 13:20 為止；**已經在跑就不啟動新的** | 收行情、判斷進場、13:20 收工 |
| PTS 出場程式 | 每天 13:25 一次，**不重跑** | 平掉微台、檢查盤中程式今天有沒有跑、清 30 天前的 log |

- **每天都叫醒，假日也是。** 是不是交易日由程式自己判斷，非交易日起來看一眼日曆就結束，不登入。
- **排程不管自動下單的開關。** 要不要真的下單只看 `config/settings.yaml`，那是唯一的切換點。
- **盤中程式的「失敗時自動重啟」就是每分鐘叫醒一次。** 工作排程器自己的「失敗時重新啟動」只管
  得到啟動失敗，程式跑起來之後當掉、被關掉、電腦重開它都不管。所以改成每分鐘叫醒、已經在跑就
  不啟動新的：當掉之後一分鐘內就回來，從部位檔與原始行情記錄接著做。正常結束之後再被叫醒，
  它自己知道今天已經收工，什麼都不做。
- **同一時間只會有一個盤中程式。** 兩個同時跑，同一分鐘會進兩次場。排程擋一次，盤中程式自己
  用 `state\intraday.lock` 再擋一次——所以排程在跑的時候手動執行 `python intraday.py`，
  它會說「另一個盤中程式正在跑」然後結束。
- **出場程式刻意不重跑。** 它告警「部位還在」之後，你可能已經自己平掉了；再跑一次，它照部位檔
  再平一次，就是反向新倉。
- **錯過就補跑**（電腦當時關機或睡著）。盤中程式照常執行；出場程式在 13:45 之後才補跑時不送單，
  發 Discord 請你在夜盤處理。
- **用電池也照跑、可以喚醒電腦。** 工作排程器的預設是用電池時不啟動、拔電就砍掉——筆電沒插電的
  那天出場程式不跑，微台就過夜。
- **沒有視窗。** 兩支程式都用 `pythonw.exe` 執行（理由見 `scheduled.py`）。要看它有沒有在跑：
  `schedule.py show`、工作管理員裡的 `pythonw.exe`，或 `logs\intraday-YYYYMMDD.log` 最後幾行。
- **網路不通時不叫醒盤中程式**（下一分鐘再看）：登入失敗今天就不再試，見下面的「排除問題」。

## 6. 電腦不能睡、要能自己登入

排程是「只在使用者登入時執行」（憑證裝在使用者帳號底下），所以電腦要**醒著而且登入著**。
鎖定畫面（Win+L）不影響執行。

- **睡眠、休眠都設成「永不」**（電源選項）。插電與用電池都要。
- **喚醒計時器**啟用（電源選項 → 進階設定 → 睡眠 → 允許喚醒計時器）。
- **自動登入**：Windows Update 半夜重開機之後要能自己登回桌面，否則停在登入畫面，什麼排程
  都不會跑。
- **Windows Update 的「使用時段」**涵蓋 08:00～14:00，把自動重開機壓到收盤之後。

## 7. 從舊機器複製資料

| 資料夾 | 要不要複製 | 為什麼 |
|--------|-----------|--------|
| `marketdata\` | ⚠️ **一定要** | 每個交易日一個檔的原始行情記錄（大台成交價與累計筆數）。長期保留、不會被清除，作者日後拿它做 tick 等級的回測，**重建不回來**。不含帳號資訊 |
| `state\` | 只有**當天盤中**換機器才需要 | 今天的部位檔、心跳記錄、停止進場記錄。13:25 的出場程式照今天的部位檔平倉：盤中換機器卻沒帶過來，它就以為今天沒有部位，微台會過夜。收盤後換機器就不必帶 |
| `logs\` | **不要** | 30 天後自動清除。裡面有未遮罩的期貨帳號與身分證字號（群益元件自己寫的 log），不要整包傳給任何人、不要放進會同步到雲端的資料夾 |
| `.env` | 重新輸入 | 見第 4 步 |

## 8. 驗收

1. `.\.venv\Scripts\python.exe -m pytest -q` 全綠。
2. `.\.venv\Scripts\python.exe tools\show_contracts.py`：真的登入群益，印出大台、小台、微台的
   近月下單代碼與最後交易日。這支工具**不可能下單**（它會先檢查自己的原始碼，而且不給期貨帳號）。
   跑完看一下 `logs\capital\`：群益元件自己的 log 應該寫在那裡，而不是 Python 的安裝資料夾。
3. `tools\schedule.py show`：兩個排程都在，「下次執行時間」對。
4. 隔一個交易日：13:25 之後沒有收到任何 Discord（模擬模式下沒有進場的日子完全安靜），
   `logs\intraday-YYYYMMDD.log` 從 08:40 寫到 13:20「13:20 收工」，`marketdata\` 多了當天的檔。
5. 打開自動下單之前，先用模擬模式至少跑一週（規格「上線前的實機驗證」）。

## log 與保留期限

`logs\` 裡的東西全部保留 30 天，由 13:25 的出場程式在做完正事之後清掉（`housekeeping.py`，
包含 `logs\capital\` 底下群益元件自己建的子資料夾）。目的是**限制個資留在磁碟上的時間**：

| 來源 | 例子 | 敏感資訊 |
|------|------|---------|
| 兩支程式的執行紀錄 | `intraday-20261109.log`、`exit-20261109.log` | 無 |
| 券商回覆的原始存檔 | `replies-20261109-091500-2315610000001.txt` | 未遮罩的期貨帳號 |
| 群益元件自己寫的 log | `logs\capital\20261109_Center.log` | 身分證字號 |

`marketdata\` 與 `state\` 不在 `logs\` 底下，不會被清。

## 排除問題

**13:25 收到「盤中程式今天沒有跑」**：看 `logs\intraday-YYYYMMDD.log` 最後幾行。常見原因：

- **登入失敗**（帳密、憑證、元件）。log 會寫群益的代碼，例如 300 密碼錯誤、307 密碼被鎖定、
  600 憑證錯誤。登入失敗之後，盤中程式**今天不再登入**（記在 `state\login-failed-YYYYMMDD.txt`）：
  帳密錯了還每分鐘再試，會把帳號鎖住，連你自己的 APP 都登不進去。排除原因之後刪掉那個檔，
  一分鐘內排程就會再叫醒它；不刪的話，下一個交易日照常登入。
- **程式在載入時就死了**（少裝套件、設定檔讀不懂）：log 裡有「盤中程式沒有正常結束」與 traceback。
  修好之後不必做什麼，下一分鐘排程就會再叫醒它。
- **log 是空的、或根本沒有這個檔**：排程沒有跑。`schedule.py show` 看「上次執行時間」與
  「上次結果」；電腦是不是睡著、停在登入畫面、或不在使用者登入的狀態。

**收到「部位檔讀不懂，盤中程式今天不進場」**：盤中程式今天不會再登入，也不會再講第二次
（心跳記錄寫了「收工了」）。照告警處理部位檔；今天不再進場。

**出場程式告警之後**：照告警自己平掉，**不要再執行出場程式**。
