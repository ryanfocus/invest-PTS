# 11: 【實機】上線驗收

**What to build:** 打開自動下單之前，把規格「上線前的實機驗證」清單逐項做完。這些都需要真實連線與真實交易日，測試涵蓋不到。

**Blocked by:** 05, 07, 10

**Status:** ready-for-human

- [ ] 模擬模式跑至少一週：模擬出來的進場時間點，和策略作者的判斷一致。
- [ ] RSI 對數字：挑一天，拿程式算出的 RSI 和看盤軟體核對。
- [ ] 昨收對數字：連續幾天，拿程式取得的昨收和期交所「一般」時段收盤價核對。
- [ ] 即時回報：找一個 OS 有下單的交易日，確認盤中即時回報會同時送到 PTS 和 OS，兩者同時登入互不干擾（規格第 57 條）。
- [ ] 成交查詢的欄位位置：PTS 第一次真實成交後取回委託與成交查詢，核對大台、小台的成交列，以及標了當沖的列（微台單腳已由 invest-os 驗證過；出場不確定時的查詢依賴這一點）。
- [ ] 第一次真實下單之後，13:30 看一次帳戶：確認券商的當沖強平真的平掉了大台／小台；確認微台確實不能標當沖。
- [ ] 小口數起步：每次進場 1 口、加碼上限調低，跑一段時間再放大。
- [ ] 出場程式在同一個行程裡第二次呼叫群益登入（13:25 網路類的登入失敗之後每分鐘重登）：元件回什麼代碼、能不能登入成功。
- [ ] 群益的「已經做過了」警告：第二次登入回 2003（ID已登入）、第二次 `ReadCertByID` 回 2005（驗章已過）時，之後照常查商品、送單、收回報。
- [ ] 實機唯讀檢查工具 `tools/show_contracts.py`：登入後印出大台、小台、微台的近月下單代碼與最後交易日（ticket 01）。
- [ ] 1 分 K 對數字：跑完一個上午，挑幾根大台 1 分 K 和看盤軟體核對（ticket 02）。
- [ ] 排程在一個真實交易日自己跑完（模擬模式），沒有人介入；排程用 `tools/schedule.py install` 建立（ticket 10）。
- [ ] 其他 ticket 的 `## Comments` 裡標「待實機驗證」的事項逐一看過（01、02、04、06、09、10 都有）。
- [ ] 每一項的結果寫在這張 ticket 底下的 `## Comments`。

## Comments

**2026-11-10（整合分支 code review 修正）：**

- 新增「出場程式在同一個行程裡第二次呼叫群益登入」一項：出場程式遇到 `LoginUnavailable`（網路、群益
  主機）會每分鐘重新登入再試（ticket 08），但同一個行程裡再呼叫一次 `SKCenterLib_LoginSetQuote`，元件
  會回什麼還沒在實機看過。做法：13:25 前拔掉網路、13:26 接回，看 `logs\exit-YYYYMMDD.log` 第二次登入
  的結果；不行的話改成每次重試都建一個新的 broker。

**2026-11-10（安全審查修正）：**

  （`SK_WARNING_CERT_VERIFIED_ALREADY`）當成憑證讀取成功（文件 6 代碼定義表，docs/capital-api.md 第 5 節）。
  實機遇到時看 log 的「群益回報已經登入過」「群益回報憑證已經驗過」之後，查商品清單、送單是不是照常。
