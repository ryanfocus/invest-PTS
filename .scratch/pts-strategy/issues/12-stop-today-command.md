# 12: 收工指令（盤中讓 PTS 今天收工）

**What to build:** 使用者盤中下一個指令讓 PTS 今天收工（規格第 61 條）：今天不再進場；帶 `--close` 時再立刻平掉 PTS 自己的口數，帳記在部位檔裡。取代「到券商 APP 手動平」——APP 是淨部位，13:25 的出場程式照部位檔還會再平一次微台，盤中程式也不知道部位已經平了。設計由 orchestrator 定案、使用者 2026-11-15 同意。

**Blocked by:** 08, 09, 10

**Status:** ready-for-agent

- [x] `tools/stop_today.py`：寫停止進場記錄（接在後面）、不登入、印出部位檔的現況與誰會了結；結果也寫進 `logs/stop-YYYYMMDD.log`；不發 Discord；非交易日什麼都不做。
- [x] 盤中程式每個時鐘事件都看一次停止進場記錄：看到就不再進場、取消等待中的突破進場（不恢復）、只記 log，寫確認記錄 `state/stop-seen-YYYYMMDD.txt`。重啟時讀到記錄、或已經因為別的原因停止進場，照樣寫。原始行情、心跳照記。
- [x] 先寫記錄、再用 `state/intraday.lock` 試鎖：盤中程式沒在跑就不必等；在跑就等確認記錄（最多 120 秒，每秒看一次），等不到就不平倉、回 1，請使用者過一兩分鐘再執行。
- [x] `--close`：13:20 之前才開始送單，送到 13:24；之後不送單，講明由誰了結。同一時間只有一個收工指令（`state/stop_today.lock`）。
- [x] `--close` 只看部位檔：沒有、讀不懂、不確定、已經平完照出場程式的規則；微台進場那一筆、有委託序號的不確定先查。
- [x] `--close` 平倉重用出場程式的平倉（登入重試、每筆最多 10 口、沒送出去每分鐘重試最多 3 次、不知道成交就查而絕不再送、每筆成交寫進部位檔、log 用「平倉成交」）；大台、小台也平，平倉單照商品標當沖。
- [x] 沒能平完時講「收工指令平了 X 口，還剩 Y 口，照常由…處理」，不叫人自己平，回 1；13:25 的出場程式只平剩下的。出場程式現有的行為與訊息一字不變。
- [x] 測試從 `intraday.run`、`stop_today.main` 接 `exit_program.run` 打進去，只用假 broker 與記錄器。
- [x] 規格、GLOSSARY、`docs/DEPLOY.md` 補上收工指令。
- [ ] 【實機】13:20 前送出的大台、小台平倉單（標當沖）券商接受，13:30 不再強平（併入 ticket 11）。

## Comments

**2026-11-15（實作者）：** 分支 `claude/pts-stop-today`。`tests/test_stop_today.py` 31 個測試，全部測試
696 個通過。兩項【實機】依規定不嘗試，**待實機驗證**（需要真實連線、真實交易日），已加進 ticket 11。

**介面：**

- `tools/stop_today.main(argv, *, connect, clock, sleep, wait_seconds=120) -> int`。
- `intraday.stop_seen_path(day)`、`intraday.is_running()`；盤中程式在 `_Trading.look_for_stop_record` 看記錄。
  `intraday._alone` 的 msvcrt 鎖搬到 `state_files.exclusive(path)`，收工指令的鎖用同一套。
- `exit_program.close_now(broker, record, *, until, clock, sleep, say, tell) -> Closing`：`_MicroExit` 多了送單期限
  `until` 與說法 `tell`（`exit_program.Tell`）；出場程式的說法搬進 `_Alarms`，一字不變。`_entry_to_look_up`
  改成公開的 `entry_to_look_up`。

**和設計不同、或設計沒寫到而由實作者決定的：**

1. **盤中留下的微台進場不確定查不到時，不印 `exit_uncertain`。** 那一則叫人「請在 13:45 前自行賣出…」，
   但部位檔還是這筆不確定的進場，13:25 的出場程式會再用序號查一次，查到全部成交就照常平倉——使用者
   先照它自己平的話，13:25 就是再平一次（反向新倉）。改印 `messages.stop_today_entry_unresolved`：同樣
   列出不確定的委託、查詢結果、部位檔的口數，但說「13:25 會再查一次，在那之前不要自己平」（同盤中那則
   「委託送出去了，但…」）。其他不確定（大台小台、平倉單、沒序號）照設計印 `exit_uncertain`：13:25 也不會送。
2. **等確認時，盤中程式結束了（鎖放掉了）也算。** 結束的行程不會再送單、不會再寫部位檔，之後被排程叫起來
   的一開始就讀到記錄。不這樣的話，剛好碰上盤中程式那一輪本來就要結束（例如非交易日、今天已經收工）
   時，會白等 120 秒再叫人重跑。
3. **不帶 `--close` 時，不確定的微台進場（有序號）回 0**，講明 13:25 會先查、不要自己平；其他不確定、
   部位檔讀不懂回 1。
4. **設計沒寫到的失敗**：停止進場記錄寫不進去（不平倉、回 1）；`.env` 缺期貨帳號（不登入、回 1）；平倉成交
   卻寫不進部位檔（13:25 一定會照舊檔再平一次，請使用者在那之前停用「PTS 出場程式」排程）；收工指令
   本身出錯（回 1，講明看哪個 log）。
5. 停止進場記錄的那一行是「`YYYY/MM/DD HH:MM:SS` 使用者手動停止進場（tools/stop_today.py）」，和盤中程式
   自己寫的行同一個格式。

**留給 orchestrator 決定的：**

- ~~出場程式「從 log 算口數」的告警沒算收工指令的平倉。~~ 安全審查後已修（見下面 2026-11-15 審查修正）。
- **使用者的停止進場記錄會讓「重啟後替上一輪補發不確定告警」不發。** 盤中程式送出進場單後、告警前當掉，
  重啟的那一輪原本看「沒有停止進場記錄」就補發「委託送出去了，但…」。這中間使用者剛好執行收工指令的話，
  記錄已經在，就不補發。收工指令自己會在主控台印出這筆不確定（兩種用法都會），13:25 的出場程式照舊處理，
  所以沒有改。
- 收工指令的平倉單如果「不知道成交」，查詢會碰到大台、小台的成交列——欄位位置還沒實機驗證（ticket 11

**2026-11-15（安全審查修正，實作者）：** 審查的六項，五項修了、一項照審查接受不動。測試 705 個全部通過。

1. **從 log 算口數的告警把收工指令的「平倉成交」也減掉**（must_fix，orchestrator 同意改出場程式的文字）：
   出場程式的三則（部位檔讀不懂、補跑時那天的部位檔讀不懂、意外中止）改成減 `logs/exit-….log` 與
   `logs/stop-….log`；盤中程式的「部位檔讀不懂」改成減 `logs/stop-….log`。
2. **空的停止進場記錄不再讓盤中程式當掉**：`write_marker` 先建檔再寫那一行，中間讀到的是空字串。空的、
   讀不懂的都算停止進場（原因不知道）；每秒的檢查整段包起來，不往外拋。
3. **13:25 出場程式等收工指令做完才讀部位檔**：拿 `state/stop_today.lock`（`exit_program.stop_today_lock_path`），
   最多等 3 分鐘，處理今天的部位時一直拿著；沒有收工指令在跑時不等。收工指令 13:25 之後才講還剩幾口時，
   改講出場程式會等它、之後照部位檔處理，有告警就照告警的口數。鎖被拿著時改講「另一個收工指令或 13:25 的
   出場程式正在處理」。
4. **查到不確定進場之後的口數**：「平了幾口」改用部位檔的平倉口數前後相減。
5. **確認記錄寫不進去就隔 10 秒再寫**，寫進去才算看過。
6. `_incomplete` 的 log 帶下單代碼、重啟後補發不確定告警的事，照審查接受，不動。
