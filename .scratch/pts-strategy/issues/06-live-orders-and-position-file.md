# 06: 真實下單：送單、部位檔、成交通知

**What to build:** 自動下單開啟時，條件成立就真的送出市價 IOC 委託，把實際成交寫進部位檔，並在每次成交後發一則 Discord。部位檔的格式在這張定案，包括「不確定」狀態，讓 07（進場失敗）和 08（出場程式）可以同時開工。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 送出的委託：市價、IOC、倉別「自動」；大台、小台標當沖，微台不標（規格第 27、28 條）。
- [ ] 交易近月；結算日當天交易當天到期的合約（規格第 9 條）。
- [ ] 記錄**實際**成交的口數和價格；IOC 只成交一部分時照實際口數記（規格第 29 條）。
- [ ] 只認自己委託序號的成交回報。OS 的單、手動下的單、連線時補送的舊回報都不會算成 PTS 的部位（規格第 56 條）。
- [ ] 部位檔內容：交易日、交易商品、下單代碼、契約月份、方向、最後交易日、狀態（已確認／不確定），以及每一筆委託的序號、口數、價格。均價由成交明細算出（規格第 52 條）。
- [ ] 部位檔先寫暫存檔再置換；每次成交之後，下一件事就是寫檔；讀不懂時大聲失敗，不能當成「沒有部位」。
- [ ] 每次成交發一則 Discord，寫出方向、觸發條件、這次口數與成交價、累計口數與均價（規格第 37 條）。
- [ ] 當天已經有部位時，交易商品一律以部位檔為準，不看設定檔（規格第 43 條）。
- [ ] 沒有停損：盤中程式不會因為虧損送出任何平倉單（規格第 36 條）。
- [ ] 自動下單關閉時，下單函式一次都沒被呼叫（零呼叫測試）。
- [ ] 測試從最上層打進去，斷言三種外部效果：送出的委託、發出的訊息、寫入的部位檔。
