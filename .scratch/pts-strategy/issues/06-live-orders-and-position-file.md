# 06: 真實下單：送單、部位檔、成交通知

**What to build:** 自動下單開啟時，條件成立就真的送出市價 IOC 委託，把實際成交寫進部位檔，並在每次成交後發一則 Discord。部位檔的格式在這張定案，包括「不確定」狀態，讓 07（進場失敗）和 08（出場程式）可以同時開工。

**Blocked by:** 04

**Status:** resolved

- [x] 送出的委託：市價、IOC、倉別「自動」；大台、小台標當沖，微台不標（規格第 27、28 條）。
- [x] 交易近月；結算日當天交易當天到期的合約（規格第 9 條）。
- [x] 記錄**實際**成交的口數和價格；IOC 只成交一部分時照實際口數記（規格第 29 條）。
- [x] 只認自己委託序號的成交回報。OS 的單、手動下的單、連線時補送的舊回報都不會算成 PTS 的部位（規格第 56 條）。
- [x] 部位檔內容：交易日、交易商品、下單代碼、契約月份、方向、最後交易日、狀態（已確認／不確定），以及每一筆委託的序號、口數、價格。均價由成交明細算出（規格第 52 條）。
- [x] 部位檔先寫暫存檔再置換；每次成交之後，下一件事就是寫檔；讀不懂時大聲失敗，不能當成「沒有部位」。
- [x] 每次成交發一則 Discord，寫出方向、觸發條件、這次口數與成交價、累計口數與均價（規格第 37 條）。
- [x] 當天已經有部位時，交易商品一律以部位檔為準，不看設定檔（規格第 43 條）。
- [x] 沒有停損：盤中程式不會因為虧損送出任何平倉單（規格第 36 條）。
- [x] 自動下單關閉時，下單函式一次都沒被呼叫（零呼叫測試）。
- [x] 測試從最上層打進去，斷言三種外部效果：送出的委託、發出的訊息、寫入的部位檔。

**實作上的決定（規格沒有逐字寫到的地方）：**

- 部位檔**一個交易日一個檔**：`state/position-YYYYMMDD.json`（`position_file.path_for`）。
  今天的檔不存在 = 今天確定沒有部位；前一天沒了結的檔不會被今天的成交覆蓋，也不會被當成今天的部位。
- 格式見 `position_file.py` 模組說明。進場、出場各一份明細（`entries`／`exits`：序號、實際口數、
  這筆的成交均價），均價由明細算、不另外存。「不確定」的那一筆記在 `uncertain`
  （`stage` ENTRY／EXIT、序號、委託口數、已知至少成交口數），`status` 和它必須同進同退。
- **0 口的委託不記**（IOC 當下沒有對手價）：沒有部位也沒有價格；只成交的時候才寫檔、才發訊息。
- 讀不懂的情況（寫到一半、缺欄位、多欄位、型別不對如 `true`／`"2"`、自相矛盾、內容是別天的）一律
  `position_file.Unreadable`。盤中程式遇到時：發一則「【要你處理】PTS 部位檔讀不懂…」，不登入、
  不進場、檔案原封不動，以 `POSITION_FILE_UNREADABLE` 正常結束（不讓排程的失敗重啟每分鐘重發）。
- 啟動時就讀部位檔（模擬模式也讀）：有今天的檔就照它的商品訂閱行情、照它的合約下單，口數與均價
  接著累計；狀態是「不確定」就整天不進場（告警當時已經發過，重啟不重發）。
- 自動下單打開時，近月合約在開盤前就向商品清單查好；查不到是 `ProductListUnavailable`，
  盤中程式在 08:40 就中止。
- **方向和手上部位相反的進場一律不做**（真實與模擬都一樣，只記 ERROR log、不告警：檔和帳上一致，
  不需要人動手）。條件 1、2 不看部位方向，重啟時昨收重查、開高／開低翻轉就會出現這種判斷；
  反向單會被倉別「自動」當成平倉，部位檔卻記成加碼。
- **成交了卻寫不進部位檔**（防毒鎖檔、磁碟滿…）：發「【要你處理】PTS 部位還在，部位檔卻沒記到這次
  成交」，寫出這次的口數、價格、委託序號、帳上與檔裡各幾口，請人自行平掉沒記到的那幾口；
  今天不再進場，程式照常跑到收工（原始行情繼續記）。不重試寫檔：告警已經叫人自己平那幾口，
  之後再補寫成功的話，出場程式會再平一次。
