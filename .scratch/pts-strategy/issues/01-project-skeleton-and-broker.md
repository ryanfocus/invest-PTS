# 01: 專案骨架與群益 broker

**What to build:** 建立 PTS 的專案骨架，並把 invest-os 裡和群益往來的部分搬過來，作為之後所有 ticket 的基礎：登入、查商品清單（近月的下單代碼與最後交易日）、送市價 IOC 委託、解析成交回報、兩類失敗的分類（「委託沒送出去」和「送出去但不知道成交」），以及測試用的假 broker。搬的時候一併修正 invest-os 的兩個已知問題。這張是預先整理，做完之後程式還不會交易。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 在沒有群益元件、沒有帳號的機器上，全部測試都能跑（規格第 59 條）。
- [ ] 設定檔能讀出交易商品、每次進場口數、加碼上限、自動下單開關、Discord 開關。缺任何一個鍵就啟動失敗並講明原因；開關必須是真正的布林值；版控裡的設定，自動下單是關閉的（規格第 42–47 條）。
- [ ] 帳號、密碼、期貨帳號、Discord webhook 從不進版控的設定檔讀取。
- [ ] 回報連線改掛 `OnSolaceReplyConnection`／`OnSolaceReplyDisconnect`。invest-os 掛的舊名在這個版本不會觸發。
- [ ] 群益元件自己寫的 log 導到專案的 log 目錄，不再寫進 Python 安裝目錄（規格第 60 條）。
- [ ] 回報解析沿用 invest-os 用真實字串驗證過的規則：只認自己委託序號的回報；判斷一筆委託是否已經結束（被拒、剩餘量取消、全部成交）。測試用的真實字串都先去識別化。
- [ ] 委託欄位可以測試：市價、IOC、倉別「自動」、當沖註記依商品而定（大台、小台標，微台不標）、每筆最多 10 口。
- [ ] 過期合約絕不送單（最後交易日已過就拒絕；結算日當天不算過期）。
- [ ] 實機唯讀檢查：有一支工具能登入，並印出大台、小台、微台的近月下單代碼與最後交易日；它啟動時會確認自己的程式碼裡沒有任何送單函式。
