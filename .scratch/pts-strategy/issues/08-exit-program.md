# 08: 出場程式（13:25）

**What to build:** 一支獨立的出場程式，13:25 由排程叫醒，單獨負責 PTS 的出場。交易微台時，平掉 PTS 自己的全部口數；交易大台、小台時不送單，交給券商 13:30 當沖強平。任何不確定的情況都不猜，改發 Discord 請使用者處理。

**Blocked by:** 06

**Status:** ready-for-agent

- [ ] 盤中程式沒在跑、或當天當掉，出場程式照常執行（規格第 49 條）。
- [ ] 非交易日完全安靜（規格第 40 條）。
- [ ] 交易商品以部位檔記載的為準，不看設定檔（規格第 43 條）。
- [ ] 微台：市價平掉 PTS 自己的全部口數，只平 PTS 開的口數；超過 10 口拆成多筆（規格第 31、32、33 條）。
- [ ] 大台、小台：不送任何出場單，結算日也一樣，由交易所以最後結算價了結（規格第 30、35 條）。
- [ ] 平倉單沒送出去：每分鐘重試、最多 3 次；只成交一部分：剩下的口數照同樣方式重試；最後仍有剩餘就告警，寫明還剩幾口（規格第 34 條）。
- [ ] 出場單送出去但不知道成交：絕不重送。改用該單的委託序號做兩段查詢（委託紀錄取得委託書號、成交紀錄加總口數）。查到全部成交就視為已平倉，不告警；只成交一部分、查不到、查詢失敗都告警，並附上查到的口數（規格第 50 條後半）。
- [ ] 部位為「不確定」：不送單，告警（規格第 50 條）。
- [ ] 部位檔讀不懂：不送單，告警（規格第 38 條）。
- [ ] 13:45 之後才補跑：不送單，告警請使用者在夜盤自行處理（規格第 55 條）。
- [ ] 平倉完成後，部位檔標記為已了結。
- [ ] 測試涵蓋以上每一種情境，斷言送出的委託、發出的訊息、部位檔內容。
