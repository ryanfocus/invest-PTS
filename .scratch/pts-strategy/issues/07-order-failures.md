# 07: 下單失敗：拒單與成交不確定

**What to build:** 進場委託出問題時，程式要分清楚兩種處境並正確收手：委託被拒（確定沒有部位），以及委託送出去了卻收不到成交回報（可能有部位）。兩種情況當天都停止進場，並發出講清楚「你要做什麼」的 Discord。

**Blocked by:** 06

**Status:** ready-for-agent

- [x] 委託被拒（確定沒送出去）：當天不再進場；Discord 只發一次，附上原因，例如保證金不足、憑證問題（規格第 51 條）。
- [x] 委託送出去但收不到成交回報：部位檔記為「不確定」，當天不再進場，發 Discord 請使用者確認帳戶（規格第 50 條前半）。
- [x] 送出之後發生的任何意外（逾時、元件壞掉）都算「送出去但不知道成交」，絕不可以當成「沒送出去」。
- [x] 告警用固定的說法分辨三種處境：「委託沒有送出去」「委託送出去了，但…」「部位還在」（規格第 41 條）。
- [x] 測試：拒單後當天停止、告警只發一次；不確定後當天停止、部位檔狀態正確。

**待實機驗證**（併入 ticket 11）：

1. **拒單原因的文字。** 委託被拒時告警附的「原因」來自 `OnNewData` 第 [44] 欄（委託單錯誤訊息），
   這一欄只有文件、沒有真實樣本（`broker/capital_wire.py` 的 `_ERROR_MSG`）。第一次真的被拒時，
   看 Discord 的原因讀不讀得懂、有沒有帶到帳號，並把那幾列去識別化存成 fixture。
2. **群益送單之後的意外。** 「送出之後任何意外都是不確定」在 broker（ticket 01）與盤中流程兩層都有
   測試，但逾時、元件拋例外的真實樣貌沒有看過；實機遇到時對照 log 與 `logs/replies-*.txt`。

**實作上的決定（規格沒有逐字寫到的地方）：**

- 三則告警的標題固定：「【要你處理】PTS 委託沒有送出去，今天不再進場」「【要你處理】PTS 委託送出去了，
  但不知道成交幾口」「【要你處理】PTS 部位還在，部位檔卻沒記到這次成交」（後者是 ticket 06 的）。
- **委託沒有送出去**：部位檔一個字都不改；告警說「不必看帳戶」，附原因，請人在明天開盤前排除；
  今天稍早已確認的口數照常了結，告警會講出來。
- **送出去但不知道成交**：`FillUnknown` 之外，`place_order` 拋出的**任何**其他例外也算（盤中流程分不出
  單出去了沒有）。部位檔改成「不確定」：確認過的成交照留在 `entries`，不確定的那一筆記在 `uncertain`
  （序號可能是空字串、委託口數、已知至少成交口數），不放進 `entries`（沒有口數也沒有價格）。
  今天第一筆就不確定時，檔是 `entries: []`、狀態「不確定」——「確定沒有部位」要先看狀態。
- 不確定告警依商品講誰來了結：大台、小台標了當沖，券商 13:30 強平；微台寫明要人自己在 13:30 前平掉，
  並寫出部位檔裡已確認的口數（出場程式看到「不確定」就整個不平，連確認過的也不平）。
- 「不確定」寫不進部位檔（檔案被鎖等）：照樣告警、照樣停止，不冒出 `run()`。告警改說檔裡還是之前的
  樣子，微台只叫人平這一筆實際成交的口數——出場程式 13:25 仍會照舊檔平那些已確認的口數。
- 「今天不再進場」只在記憶體裡：被拒之後若盤中程式因別的原因重啟，會再試一次（可能再告警一次）。
  「不確定」寫在部位檔裡，重啟後照樣不進場（ticket 06 已做）。
- 拿掉 ticket 06 留下的防護：`intraday.main()` 不再因為自動下單打開而拒絕啟動。
