# 07: 下單失敗：拒單與成交不確定

**What to build:** 進場委託出問題時，程式要分清楚兩種處境並正確收手：委託被拒（確定沒有部位），以及委託送出去了卻收不到成交回報（可能有部位）。兩種情況當天都停止進場，並發出講清楚「你要做什麼」的 Discord。

**Blocked by:** 06

**Status:** resolved

- [x] 委託被拒（確定沒送出去）：當天不再進場；Discord 只發一次，附上原因，例如保證金不足、憑證問題（規格第 51 條）。
- [x] 委託送出去但收不到成交回報：部位檔記為「不確定」，當天不再進場，發 Discord 請使用者確認帳戶（規格第 50 條前半）。
- [x] 送出之後發生的任何意外（逾時、元件壞掉）都算「送出去但不知道成交」，絕不可以當成「沒送出去」。
- [x] 告警用固定的說法分辨三種處境：「委託沒有送出去」「委託送出去了，但…」「部位還在」（規格第 41 條）。
- [x] 測試：拒單後當天停止、告警只發一次；不確定後當天停止、部位檔狀態正確。

  今天第一筆就不確定時，檔是 `entries: []`、狀態「不確定」——「確定沒有部位」要先看狀態。

**2026-11-10（審查修正）：「今天不再進場」改成寫檔。** 原本只在記憶體裡，審查指出盤中程式
當天被重啟（規格第 48 條）時，被拒的單會再送一次、再告警一次，違反第 51 條與上面第一項驗收條件；
「不確定」或成交寫不進部位檔時，重啟後部位檔看不出今天出過事，會照常加碼。

- 三種處境停止進場時，都先在部位檔旁邊寫一個停止進場記錄（`state/entries-stopped-YYYYMMDD.txt`，
  `intraday.stop_path`），再發告警。重啟時看到它就不進場、不再告警。
- **檔案存在就是停過**，內容只是寫給人看的時間與原因；讀不懂也照樣不進場，不讓程式當掉。
- 直接附加寫入、不經過 `os.replace`：部位檔被鎖住的時候（最需要它的時候）照樣寫得進去。
- 寫不進去只記 log、照樣發告警，今天這一輪照樣停止（重啟後就記不得了，這是兩個檔都寫不進去的
  情況，不再往下處理）。
